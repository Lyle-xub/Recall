# Recall 0.3 macOS 验证记录

日期：2026-09-25。环境：Apple Silicon、macOS 27.2、Xcode 27 SDK。范围：macOS 更名、图标与录制修复；Windows 源码与发行包保持原样。

## 修复与依据

1. 原有临时签名在重新构建后改变了 cdhash。系统 TCC 日志明确记录已有屏幕录制授权的代码要求与运行中的旧 Rewind 二进制不匹配。用户处理权限后，本轮后续更新不再修改权限；多次签名更新后的启动均记录 `screenPermission=true`。
2. 发布构建改为固定 Developer ID 签名，应用标识保持 `studio.rewind.replica`，数据、Keychain、已下载模型继续使用原目录。构建脚本无证书时失败，只有明确标记的 CI 编译产物允许临时签名。增加单实例控制，避免两个副本同时录制或抢占快捷键。
3. ScreenCaptureKit 返回的显示器列表是 `5,1,4`，此前直接选择第一项，得到 1920×1200 的另一块屏幕。现在默认匹配 `CGMainDisplayID()`，本机为 1，实际记录 3024×1964 主屏幕；明确指定但已断开的显示器会提示重新选择。
4. 隐藏悬浮层时同时调用原生应用隐藏，避免自身仍为前台进程而被录制排除规则持续跳过。录制失败和停止均清理流、音轨和回调状态；旧片段的异步回调不能写入新片段。
5. 会议窗口列表的刷新改为独立任务，普通屏幕索引不再等待可选窗口枚举。修复前，视频已有内容但索引停在首帧处理；修复后每约 3 秒完成一张屏幕索引，OCR 耗时约 0.4–0.7 秒。
6. 在本机点视频回放时，系统 `_AVKit_SwiftUI` 曾因 `VideoPlayerView` 父类元数据解析失败而退出。改用原生 AppKit `AVPlayerView`，回放与暂停复测通过。
7. 名称统一为 Recall，新增蓝色回溯环应用图标和单色菜单栏图标。菜单栏录制状态与应用状态同步。安装位置为 `/Applications/Recall.app`。

## 真实录制与交互

测试文档是 `docs/recording-check.txt`，由文本编辑应用显示，通过 ScreenCaptureKit 录制；未将文档直接导入数据库。

- 录制片段 `ABEEBB87-9EF3-4316-ABD4-7A995169D404`：会话约 32.09 秒，MP4 时长 31.7 秒、12,477,495 字节，3024×1964，AVFoundation 解码成功。
- 生成 11 张 `demo=0` 的索引帧，11 张均包含测试词 `silver moon` 与 `产品设计`。
- 通过 Recall 搜索框分别检索英文、中文，结果显示实际文本编辑窗口。
- 点击结果，历史画面显示真实记录像素；底部时间线拖动后，时间从 06:25:48 回退到 06:25:32，对应历史帧随之切换。
- 在历史画面直接拖选 `silver moon`，按 ⌘C，然后在搜索框按 ⌘V，字段得到准确的 `silver moon` 并返回记录，验证原生 Live Text 范围复制。
- 原生视频播放器启动后显示播放状态、约 00:18 的播放位置与 00:32 总时长；点击暂停后切换为暂停状态，没有再次退出。
- 最终安装版本再次启动录制并保存新片段；测试结束已暂停录制，记录保存在用户本地资料库。
- 多次更新后的录制均使用用户已配置的权限，无需重置授权。

- 显式启用 `LocalInferenceTests/testInstalledModelsEndToEnd`：使用已安装、同一 Developer ID 签名的 llama.cpp / whisper.cpp 和已下载权重，Qwen 返回正确数字与来源标记，Whisper 转写合成语音通过，耗时约 38.7 秒。

- 新的 `Recall-macOS.zip` 与校验清单位于 `release`。旧 Mac 开发副本保存在 `release/previous`，避免误打开。

## 验证边界

此次录屏关闭系统音频与麦克风；真实会议双音轨、各个外接显示器逐一切换和长时间运行没有完成验收。Whisper 的本轮推理测试使用合成语音，不能代替真实会议录音测试。

桌面悬浮层保留透明背景、底部渐变模糊及高于 Dock 的窗口层级；历史画面中可见底部模糊覆盖 Dock。UI 工具的窗口截图不能完整呈现实时桌面的合成效果，不将其白色背景当作桌面视觉验收证据。OCR / Live Text 受文字尺寸、清晰度、语言及受保护内容限制，无法保证每个字符均正确识别。
