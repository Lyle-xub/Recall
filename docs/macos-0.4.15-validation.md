# Recall 0.4.15：界面内暂停录制与跨行文字选择

2026-09-25，macOS build 22。Windows 未改动。

## 录制状态

- 时间线、搜索、图片详情、Ask、设置、App usage 共享父悬浮窗口的可见性。打开窗口立即禁止接受新截图，并结束 ScreenCaptureKit 的屏幕及两路音频流；进入其他页面不会恢复录制。
- 用户的录制意愿与实际流状态分离。界面关闭动画结束后，延迟 300 ms 恢复此前启用的录制；快速关闭再打开会取消这次恢复。手动暂停始终保留。在界面中点击 Start recording 只准备录制，保持当前界面，关闭后才开始。
- 启动、停止、五分钟分段和退出使用同一个串行协调器；启动期间打开界面也会收束到暂停状态。退出先撤销录制意愿，动画完成不会误启动。
- 结束流后再等待已接受截图落盘。截图在打开界面前已经接受时，仍可能在打开后的短时间内完成保存；不会因此采集新的 Recall 内容。
- 自动 OCR、转写及存储优化在当前工作单元安全结束后等待界面关闭。显式运行存储优化可通过 Continue while open 继续。待转写会话 ID 保存到本地，可跨重启继续。

## 流畅度

- 原始截图保存、OCR 图片归档、索引提交和视频替换移到后台；应用使用时长以后台串行写入保持顺序。录制停止会等待已提交的使用时长写完。
- UI 元数据读取使用独立 WAL 读取连接，避免等待图片归档持有的写入锁。
- 时间线预览与搜索缩略图使用独立解码队列。拖动时合并同一显示帧内的更新，取消失效加载；缩小回看卡片使用最长边 2048 像素的显示副本，详情使用 3072 像素。原始截图、OCR 文字和坐标不改变。
- 会议画中画缩略图异步读取，避免 SwiftUI 每次更新都同步解码图片。

## 文字选择

- 不再为截图上的每一行创建 NSTextView，也不再使用会重新覆盖像素的 Live Text 背景层。整个截图共用一个选择视图，只绘制 25% 透明度的蓝色选区。
- 支持连续多行、反向拖选、双击选词、三击选行、Shift 扩选、方向键、⌘A 和 ⌘C。复制保留行间换行，Unicode 组合字符和 emoji 不拆开。
- 跨行拖选根据首尾行的水平范围过滤其他列，避免包含右侧不相关内容。⌘A 明确选择整张截图的全部 OCR 文本。
- 只有部分选中的端点行需要文字排版，完整中间行直接使用已存坐标；最多保留四个行布局。没有 OCR 的稳定画面可按需在后台识别，索引过的画面不会重新 OCR。
