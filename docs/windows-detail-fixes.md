# Windows 交互与视频细节修复

新版文件：`Recall-Windows-x64-detail-fixes.zip`。请先从旧版托盘菜单退出 Recall，再完整解压并运行新版 `Recall/Recall.exe`。已有资料库无需移动。当前运行的旧程序不会自动更新。

## 本轮完成

1. 应用图标：补充进程路径、App Paths、打包应用图标解析；失败项可重试，成功图像缓存复用。图标保持比例并居中，时间线刷新时避免闪回占位符。确实无法获取图标时显示统一应用符号，不再用字母代替。
2. Rewind：截图和视频统一 12 px 圆角；视频采用 MediaPlayer 解码、Win2D/XAML 显示，保留原生播放、暂停与定位控件，消除独立视频层绕过圆角和退出页面后的残留。每次播放独立创建并释放播放器，异步打开和失败回调都有版本校验；未完成录制的文件暂不播放，坏文件显示错误并回退到截图。
3. 视频方向：正常录屏保持原方向；当 90°/270° 元数据与对应截图的宽高比冲突，且反向宽高比吻合时自动校正。无法判断的旧视频可使用“Rotate video 90 degrees”按钮；手动角度在当前详情页内保留。合成的 90° 标记错误已复现并验证自动校正，正常视频和四个手动方向均已验证。
4. 莱茵页面：支持横向和纵向拖动，拖动与点击展开分开判定；时间线停留约 250 ms 或松手后展开对应记录卡片，继续拖动时切换预览。没有录制内容的时间段不会编造卡片。
5. 搜索框：玻璃只绘制在外层边框，原生文字区域保持透明；文字编辑器保留系统桌面玻璃与高光，避免原生编辑器中间表面与窗口内折射互相采样，实测中英文输入不再出现矩形填充。
6. 设置：只保留玻璃导航；内容分组、按钮、输入框、开关、密码框和下拉框恢复 Windows 风格，支持浅色和深色。切换标签重置滚动位置。字体沿用 Segoe UI Variable 的标题/正文/小字层级及系统中文回退。

## 校验

97 项核心测试通过，含 8 个录屏方向边界用例。进行了多轮编译、截图查看和原生鼠标/键盘操作；当前报告保留 87 份通过的状态记录。专项覆盖播放、四方向旋转、异常元数据自动校正、坏视频回退、重播、退出和重新打开，以及 5 个设置标签的浅深色状态。还完成 17 个常规页面状态、动画及减少动态效果回归、17 个隐藏/重开/快速打断关闭状态。

原生操作单独验证：鼠标拖拽莱茵画布、拖动时间线后展开对应卡片、输入中英文、播放/暂停/返回图片和 Esc。详细实际执行结果见 `native-detail-checks.json`；截图的前后变化比单独的状态指标更直观。

测试使用 Windows 11 build 22621、1280×800、100% 缩放及独立合成资料库，未开启真实录制。普通启动的捕获排除实现保留，本轮未关闭用户正在运行的旧版来替换普通实例。原始异常录屏尚未提供，因此尚不能确认用户那条视频是否属于同一种方向元数据问题。多显示器、其他 GPU 和缩放比例未在本机复测。

整体 Mac 90% 视觉一致性仍未量化证明；本轮重点修复 Windows 交互和显示问题，没有把合成样本或局部相似度当作整体证明。

## 开发者复现

先准备现有 visual-parity 合成图片和 fixture.json。运行 `python scripts/prepare-windows-video-fixtures.py <directory>`，启动 `Recall.exe --visual-parity <directory>` 自动生成 20 秒视频；退出该测试实例后再次运行准备脚本，产生异常旋转与坏文件样本。重新启动测试实例，然后运行 `scripts/test-windows-details.ps1 -Directory <directory>`。原生鼠标/键盘校验需在交互桌面进行。

视频显示使用 Microsoft 官方 MediaPlayer frame-server API；XAML 图像树负责等比例显示和圆角裁剪。自动方向策略只在对应录屏截图支持该判断时处理 90°/270° 标记，不全局强制旋转。参考：https://learn.microsoft.com/en-us/windows/apps/develop/media-playback/play-audio-and-video-with-mediaplayer
