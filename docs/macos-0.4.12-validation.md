# Recall 0.4.12 图片与视频存储优化

2026-09-25，macOS 构建 18，Windows 不变。

## 行为

- Storage → Smart storage 改为 **Optimize images & videos**，统一扫描旧图片与已结束视频，分别显示处理数量、总进度及本次运行累计释放空间；可暂停，再点击按钮继续未完成项目。
- 旧主画面、会议图片和回收站中仍可恢复的图片按文件处理，共享图片不会按时间点重复编码。未完成 OCR 的原图跳过，原有索引队列仍负责先识别后归档；现代 `screen-<SHA256>` 归档图不重复有损压缩。
- 对旧 JPEG / PNG 在完整尺寸下尝试 PNG / HEIC 0.92，只在候选至少小 12%、尺寸一致、原尺寸 RGB 均方误差不超过 6.5025（约 40 dB PSNR）、高对比边缘平均误差不超过 5/255、透明度不变时接受。失败、旋转、动画或特殊图像保留原始编码。质量检查不调用 OCR；数据库里的原始文字和坐标不变。
- 即使无须重新编码，也可将完全相同的原始文件按内容哈希共享。所有时间点和收藏保留，不做感知去重，不降低截图分辨率。HEIC 是有损编码，像素门槛并不保证任意文字的再次 OCR 与原图逐字相同。
- 替换前复核来源内容 SHA-256、引用和待索引状态；新图写完并同步后，在同一事务中更新所有主画面/会议/回收站引用，最后移除无人引用的原图。原 OCR、位置、链接、时间及 FTS 均不重写。
- 数据库保存阶段记录和替换映射，重启只回收已校验、无人引用的文件。缓存页面与异步查询结果同步映射新路径，避免优化时预览空白，以及旧页面的收藏/回收站操作写回失效路径。
- 单后台队列、逐图释放内存；每项之间留出调度时间。空间图表刷新限制为两秒一次，避免批量优化反复扫描整个媒体目录。

- 完整测试 100 项：95 项通过、5 项可选集成检查跳过，零失败。上面的真实图片集成检查另在 Release 中显式运行并通过。
