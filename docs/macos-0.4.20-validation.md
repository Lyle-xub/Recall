# Recall 0.4.20：减少重复存储与媒体圆角

## 存储变化

- 原始截图逐像素 SHA-256 比较，包含尺寸、像素格式与颜色配置，不做感知相似合并。忽略非图像的行填充字节。同一应用、标题、录制段与连续区间的相同画面更新 `endTimestamp`，不增加截图或 OCR 任务；应用使用清单独立继续更新。切换应用或录制中断保留独立时间记录，但可共享相同图片与已完成 OCR。
- 新视频直接以最长边 960、最高 1 fps、目标 150 kbps HEVC 编码（不可用时 H.264），截图分支保留原分辨率。静止视频在结束时补足持续时间，无原分辨率中间视频或二次转码。
- 新视频没有内嵌音轨，回放通过 AVComposition 引用原系统声音与麦克风 AAC 文件，并保留各自开始偏移。音频不重新压缩。历史视频仅在独立音轨文件、时长、可解码性和修改时间校验通过后去掉重复音频；已是轻量视频的片段仅重新封装。无法证明独立音轨完整的旧记录保留原视频音频。
- 完全相同的 OCR 文字及坐标共用不可变内容记录；每张图保留原 region ID，导出与选择内容不变。标题和 OCR 全文检索使用 SQLite FTS5 外部内容表与同步触发器。迁移为原子事务，随后后台压缩数据库；存储优化按钮同时包含索引压缩。

## 图片与视频圆角

- 图片和文字选择层放入同一原生裁切面，圆角沿等比缩放后的真实图片边缘计算；不再裁切带留白的外层容器。图片连续圆角为 22 pt，原有跨行拖选与复制保持。
- AVPlayerView 使用原生图层遮罩，对实际视频矩形裁切四角，随尺寸变化更新；视频圆角同为 22 pt。

## 已完成验证

- 全套 143 项检查：135 通过，8 项需显式启用的可选检查跳过，0 失败。新增图片裁切后，4 项跨行文字选择与渲染回归检查再次通过。
- 连续 61 次完全相同的截图只保存一个画面区间、一张图和一次待识别任务；一个像素变化生成新记录。应用切换、中断与重新出现的相同画面仍可区分。
- 1727 条真实历史记录的数据库副本迁移后，所有原始字段逐项哈希相同。安装后的真实库再次检查 1727 条全部相同，设置不变，SQLite `quick_check` 为 `ok`。
- 真实数据库从 126,312,448 字节缩为 93,974,528 字节，约减少 25.6%；这仅是本机索引数据库的实测，不代表整体媒体或每周存储收益。
- 合成 3024×1964 静止视频直接编码为 960×622，10 秒，1619 字节，无内嵌音频，末尾可解码。静止素材结果不用于估算动态屏幕视频大小。
- 双 AAC 音轨回放偏移 0.25/0.75 秒正确；旧视频去重后压缩视频数据与两份音频文件逐字节相同。测试片段视频文件从 155648 减至 4096 字节，音频保留在独立文件中。
- 200 条带 OCR 记录读取约 10 ms；1000 次已缓存时间线查询约 7.5 ms。这些是本机测试数据路径耗时，并非原生界面的帧率承诺。

## 安装后实机检查

- 保持原 Developer ID 签名，安装到 `/Applications/Recall.app`，版本 0.4.20 / build 27；无须再次授权。
- 首次实测发现给 ScreenCaptureKit 添加第二个屏幕输出会让截图分支收不到画面。已改为一个系统屏幕输出分发给原图与视频分支，分别在后台处理，并新增分发回归检查。
- 修复后真实采集 40.48 秒：13 张 3024×1964 的原始精度截图，PP-OCRv6 Small 识别完成；视频 960×622，名义帧率 1.034 fps（包含结束时的保持帧），无内嵌音轨。回放组合含系统声音与麦克风两条音轨，原生播放器实际启动并推进时间。
- 实际查看历史图片和视频，四个圆角正常；带转写侧栏时图片角落仍贴合真实画面，原图跨行拖选产生完整连续文本。
- 最终核对原有 1727 条图片记录、720 条转写记录均完全保留，设置未变。测试结束恢复原手动暂停状态。

原有库迁移前副本保留在本地 `.test-data/420/pre-migration.sqlite`；测试不永久清理用户记录。

实现参考：[SQLite FTS5 外部内容表](https://www.sqlite.org/fts5.html)、[Apple 像素缓冲视频写入](https://developer.apple.com/documentation/avfoundation/avassetwriterinputpixelbufferadaptor/append(_:withpresentationtime:))。
