# Recall 0.4.8 搜索、问答与每日使用时间

2026-09-25，macOS，构建 14。Windows 保持原构建。

## 搜索

实库只读查询确认 `paper` 原本已匹配 7 张 Obsidian 画面，但按时间排序后的前 200 张全属于 ChatGPT 和微信。`papers` 匹配量较少，因此旧界面能够显示 Obsidian；这不是 OCR 丢失。

- 对完整匹配集排序后分页：先显示每个应用的一条最佳结果，再按小批次展开其他画面。
- 使用已有 FTS5 文字索引处理词语前缀与重音字符，支持常见英文单复数、多词不同顺序及跨 OCR 换行。中文连续文本和特殊字符保留字面查询，双引号表示精确短语。
- 窗口标题、应用名、OCR 和同会话附近的转写均可检索。星标、时间、应用、回收站和真实数据过滤保持生效。
- 修正 200 条初始结果与旧 500 条加载门槛不一致的问题；后台读取额外一条确定是否还有结果。换查询或筛选时回到列表顶部。缩略图高亮跟随拆词、词形和重音匹配；缺失窗口标题时显示应用名。
- 真实记录库 `paper` 检索返回 200 条、覆盖 8 个应用，包含 Obsidian；开发测试环境单次耗时约 0.25–0.6 秒。此数字是数据库查询及反序列化时间，不是 UI 帧率。

## Ask Recall

- 移除全部示例问题，保留简洁空状态、真实模型信息、当前检索范围和输入框。
- 独立数据库连接在后台检索，过滤中英文问句虚词；明确追问可延续上一问题主题；今天、昨天、本周及过去七天按本地日期限制来源。
- 相同画面的重复记录去重，并兼顾不同应用；找不到相关主题时直接说明，没有无关的最近记录回退。宽泛的近期总结允许使用近期记录。
- 转写限于来源画面附近；长 OCR 提取匹配位置附近的片段，避免相关答案恰好被前缀截断。
- 显示检索和回答进度，流式界面更新合并到约每 40 毫秒一次，支持停止、重试、复制回答和返回来源画面。取消或开始新对话后不会应用旧请求结果。
- 实际运行已安装的 Qwen3 本地模型，以临时测试库中的长文本预算记录检索并回答，验证数字 42 和来源 [1]；未调用用户在线模型，也未向在线服务发送记忆内容。

## 每日应用使用时间

- 入口：Recall 浮层菜单、菜单栏状态菜单中的 **App usage…**。
- 原生 SwiftUI / Swift Charts 白色面板：当天总时长、周柱状图、小时分布、分类图例、应用图标与排行、应用筛选。可选择日期、前后切换、回到今天，或点击周图选择日期；每 30 秒刷新。
- 统计已有前台应用活动区间，不依赖 OCR 截图是否完成。重叠区间以较新的前台切换为准，避免累计重复；按本地日历拆分午夜和小时，覆盖 23 / 25 小时夏令时日期。
- 暂停录制、不可用屏幕和没有数据的间隔不计入。排除应用仅显示 Private activity，不恢复或推断其名称。数据起始时间及口径在页面底部说明，历史保留周期与已有记录设置一致。
- 分类依据已安装应用的类别元数据，缺失时归入 Other。周平均值按有记录的日期计算，提示说明此口径。
